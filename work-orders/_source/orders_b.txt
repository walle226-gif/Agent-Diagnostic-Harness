=== B01 | 1 | feature | Ranges and summary functions
Now: A formula can only refer to single cells.
Should: Formulas accept ranges such as A1:B3 and the functions SUM, AVERAGE, MIN, MAX and COUNT, with any number of arguments. Function names are case-insensitive, and AVERAGE and COUNT ignore empty cells.
P: Tokenizer and parser support for ranges and function calls.
D: Parser tests cover "=SUM(A1:B3)", "=sum(a1, 2)" and nested calls.
P: The five functions in the evaluator.
D: Tests cover each function, empty cells, and "=SUM(A1:A3, MAX(B1:B2)*2)".

=== B02 | 1 | performance | Recalculate only what changed
Now: Changing one cell re-evaluates every cell in the sheet.
Should: A dependency graph built from the formulas. Editing a cell re-evaluates only the cells that depend on it, directly or indirectly, in dependency order (a topological sort).
P: Building the graph from parsed references, ranges included.
D: A test checks the dependents of a cell in a small sheet.
P: Incremental recalculation, with an evaluation counter that tests can read.
D: A test with 1,000 cells changes one input and counts exactly the expected number of evaluations.

=== B03 | 1 | feature | Circular references
Now: A formula that refers to itself, directly or through other cells, hangs or crashes.
Should: Every cell in a cycle shows #CYCLE!, and so does every cell that depends on one. Breaking the cycle recalculates the cells normally.
P: Cycle detection in the dependency graph.
D: Tests cover a self-reference, a cycle of three cells, and a cell that depends on a cycle.
P: Recovery when the cycle is broken.
D: A test breaks a cycle by editing one cell, and all affected cells get numbers again.

=== B04 | 1 | feature | Error values
Now: Bad formulas give crashes or JavaScript values like NaN and Infinity.
Should: The error values #DIV/0!, #REF!, #NAME? and #VALUE! are produced where they apply and pass through operators and functions. SUM over a range that contains an error returns that error. IFERROR(x, fallback) catches them.
P: Producing and passing on the four errors.
D: A test per error, plus one where an error passes through two levels of formulas.
P: The IFERROR function.
D: Tests cover IFERROR with and without an error.

=== B05 | 1 | feature | Text and comparisons
Now: Formulas only work with numbers.
Should: String literals ("abc", with "" for a quote inside), & for joining text, the comparisons = <> < > <= >= giving TRUE or FALSE, and the functions LEN, UPPER and LOWER. Text compares case-insensitively, and any text is greater than any number.
P: String literals in the tokenizer.
D: Tests cover an empty string and an embedded quote.
P: The & operator and the comparisons.
D: Tests cover text against text, number against text, and TRUE/FALSE results.
P: LEN, UPPER and LOWER, correct for å, ä and ö.
D: Tests include "=UPPER(\"åäö\")".

=== B06 | 1 | feature | Lazy IF and logic functions
Now: There is no way to choose between values.
Should: IF(condition, a, b) evaluates only the branch it returns, so "=IF(TRUE,1,1/0)" is 1. AND, OR and NOT work, and an error only matters if its argument is actually evaluated.
P: IF with lazy evaluation.
D: Tests include "=IF(TRUE,1,1/0)" giving 1 and "=IF(FALSE,1,1/0)" giving #DIV/0!.
P: AND, OR and NOT.
D: Tests cover each function, including OR stopping at the first TRUE.

=== B08b | 1 | feature | Percent and power operators
Now: Formulas have no percent sign and no way to raise a number to a power.
Should: A postfix % divides by 100, and ^ raises to a power and groups from the right (2^3^2 is 2^9). As in other spreadsheets, unary minus binds tighter than ^, so -2^2 is 4; this is documented in the README.
P: Tokenizer and parser support for % and ^ with the precedence above.
D: Parser tests cover 2^3^2, -2^2, 50% and 2*3^2.
P: Evaluation of both operators.
D: Tests check the values of the four formulas above and of =10%*A1.
P: An "Operators" section in the README with the precedence table, including the -2^2 rule.
D: A test fails if any operator the tokenizer knows is missing from that section.
