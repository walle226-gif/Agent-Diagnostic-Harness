What it isVad det är

An agent that works inside a project folder: it reads files, edits them, runs commands and tests, inspects git, and reports what actually happened. It talks to a model hosted locally, so it is usable in environments where a cloud coding assistant is not permitted: defence, medical, legal, industrial, or anywhere a source tree cannot be sent to a third party.

The code it writes is yours. It is produced on your own machine, no cloud provider's terms apply to it, and the model runs under the open Apache 2.0 licence.

The same engine drives three interfaces, so a team can use it wherever they already work.

It scales with the hardware you give it. The tested configuration fits a single 16 GB desktop card, which is the floor rather than the target: the same engine runs against a workstation card, a shared server GPU or a rack of them, with a larger model behind the same contract and no change to how anyone works. One developer's machine and a department's server are the same product with a different model behind it.

En agent som arbetar inne i en projektmapp: den läser filer, ändrar dem, kör kommandon och tester, tittar i git och rapporterar vad som faktiskt hände. Den pratar med en modell som körs lokalt, vilket gör den användbar där molnbaserade kodassistenter inte är tillåtna: försvar, vård, juridik, industri, eller överallt där en kodbas inte får skickas till tredje part.

Koden den skriver är er. Den skapas på er egen maskin, inga villkor från någon molnleverantör gäller för den, och modellen körs under den öppna licensen Apache 2.0.

Samma motor driver tre gränssnitt, så teamet kan använda den där de redan arbetar.

Den skalar med hårdvaran ni ger den. Den testade konfigurationen ryms på ett enda 16 GB-kort i en vanlig dator, och det är golvet snarare än målet: samma motor kör mot ett arbetsstationskort, ett delat server-GPU eller ett rack av dem, med en större modell bakom samma kontrakt och utan att någon behöver ändra sitt arbetssätt. En utvecklares dator och en avdelnings server är samma produkt med olika modell bakom.

Example · 29 SeptemberExempel · 29 september

It proves its own fixes. Enquiries from the company's website were being saved under the website's name instead of the customer's, so a new lead lost its name. The tests were green both before and after the fix, and the agent pointed out that they therefore proved nothing. It rebuilt the real email and showed the difference: the old code saved the enquiry as "Website Form", the fixed code under the customer's own name. Then it added that case to the tests, which now fail on the old code and pass on the new. We checked this separately, on a copy: with the old code, 4 of the new checks fail.

Den bevisar sina egna rättningar. Förfrågningar från företagets hemsida sparades under webbplatsens namn i stället för kundens, så att en ny kund tappade sitt namn. The studies run on the developer's own card and on rented graphics cards.

Why it is trustworthy on a real codebaseVarför den går att lita på i en riktig kodbas

Nothing runs unapprovedInget körs utan godkännande

Every file write, every shell command and every commit is shown and approved before it happens. A denied action is explained to the agent rather than retried.

Varje filskrivning, varje kommando och varje incheckning visas och godkänns innan den sker. Ett nekat steg förklaras för agenten i stället för att försökas igen.

There is always a way backDet finns alltid en väg tillbaka

The project is snapshotted before the first destructive action of a turn, and the snapshot lives outside the project folder: because an undo history stored inside the thing it protects is not an undo history.

A recursive delete whose target is computed rather than named is refused outright.

Projektet ögonblickskopieras före första förstörande steget i en tur, och kopian ligger utanför projektmappen: en ångra-historik som sparas inuti det den skyddar är ingen ångra-historik.

En rekursiv radering vars mål räknas fram i stället för att namnges nekas rakt av.

Claims are checkedPåståenden kontrolleras

Written code is compile-checked immediately. A test file that never imports the module it claims to test does not count as verification. A run that contradicts the agent's own summary is caught and put back in front of it.

The agent must state what it expects before running a command, so a result that disagrees with the prediction cannot quietly become the story afterwards.

Skriven kod kompileringskontrolleras direkt. En testfil som aldrig importerar modulen den påstår sig testa räknas inte som verifiering. En körning som motsäger agentens egen sammanfattning fångas upp och läggs tillbaka framför den.

Agenten måste säga vad den förväntar sig innan ett kommando körs, så att ett resultat som motsäger förutsägelsen inte i efterhand kan bli den nya berättelsen.

It runs what it buildsDen kör det den bygger

It can launch a program, watch it, measure the window it opened, and drive an interactive command-line program by typing scripted input into it, which is how it catches the class of bug where every unit test passes and the actual program does nothing.

Den kan starta ett program, iaktta det, mäta fönstret det öppnade och styra ett interaktivt kommandoradsprogram genom att mata in färdiga rader, vilket är så den fångar den sortens fel där alla enhetstester går igenom och själva programmet inte gör någonting.

It tunes the machineDen trimmar maskinen

GPU memory cost per model is measured once and cached rather than guessed: measurements on this hardware showed a 13× spread between models that parameter counts do not predict. Context length, batch sizes and offload are set from those measurements.

Grafikminnets kostnad per modell mäts en gång och sparas i stället för att gissas: mätningar på den här hårdvaran visade 13 gångers spridning mellan modeller, vilket antalet parametrar inte förutsäger. Kontextlängd, batchstorlekar och GPU-avlastning sätts utifrån de mätningarna.

What the measurements showedVad mätningarna visade

This agent was not just built: it was studied. Thousands of recorded work sessions, each one designed like a small experiment: predict first, run once, read everything, change one thing. Since late August the measurement work has had its own workbench, its own rules and its own rented hardware, and the agent is the thing it measures. These lessons now live in the product.Den här agenten byggdes inte bara: den studerades. Tusentals inspelade arbetspass, vart och ett upplagt som ett litet experiment: förutsäg först, kör en gång, läs allt, ändra en sak. Sedan slutet av augusti har mätarbetet en egen verkstad, egna regler och egen hyrd hårdvara, och agenten är det som mäts. De här lärdomarna sitter numera i produkten.

An independent refereeEn oberoende domare

Correctness is decided by a separate referee program that runs the finished code and compares the results with answers fixed in advance, not by the agent's own tests.

Korrekthet avgörs av ett separat domarprogram som kör den färdiga koden och jämför resultaten med facit som bestämts i förväg, inte av agentens egna tester.

Proven work is saved instantlyBevisat arbete sparas direkt

The moment a fix is proven correct, a copy is stored outside the agent's reach, automatically, before anything else can happen. Proven work is never left where a later cleanup step can reach it.

I samma ögonblick som en lagning bevisats korrekt sparas en kopia utom räckhåll för agenten, automatiskt, innan något annat hinner ske. Bevisat arbete lämnas aldrig kvar där ett senare upprensningssteg kan nå det.

Its reasoning is on recordDess resonemang sparas

The agent's step-by-step thinking is captured to disk. When something goes wrong, the reason can be read afterwards rather than guessed at.

Agentens steg-för-steg-tänkande sparas till disk. När något går fel kan orsaken läsas i efterhand i stället för att gissas.

Models chosen by measurementModeller väljs efter mätning

Models differ in pace, habits and strengths. They are compared here on identical tasks with identical referees. One finding: a small, fast model measurably solved a hard bug that a model four times its size could not, so the shipped configuration comes from measurements, not marketing.

Modeller skiljer sig i tempo, vanor och styrkor. Här jämförs de på identiska uppgifter med identiska domare. Ett fynd: en liten, snabb modell löste bevisligen en svår bugg som en modell fyra gånger så stor inte klarade, så den levererade konfigurationen kommer från mätningar, inte marknadsföring.

How you write the task changes the workHur uppgiften skrivs ändrar arbetet

One study took a single task and removed a contradiction from its wording, nothing else. The agent's planning reply halved. The effect held on a second machine with a different graphics card, and a length-matched placebo sentence did not reproduce it, so it is the contradiction and not the extra words.

That is why the product now reads a task before it starts and puts two measured shapes of a self-contradicting request back to the person as a question, instead of quietly picking one reading.

En studie tog en enda uppgift och tog bort en motsägelse i formuleringen, inget annat. Agentens planeringssvar halverades. Effekten höll på en andra maskin med ett annat grafikkort, och en lika lång placebomening återskapade den inte, alltså är det motsägelsen och inte de extra orden.

Därför läser produkten numera uppgiften innan den börjar och lägger två uppmätta former av en motsägelsefull beställning tillbaka till personen som en fråga, i stället för att tyst välja en tolkning.

Its own verification was auditedDess egen verifiering granskades

The agent is reminded when it claims a fix without exercising it. Every real firing of that rule was then audited against the recorded sessions, and the rule was rewritten from what the audit showed: it now reads what a real test of that specific edit looks like, and the check that runs the agent's own tests to watch them fail first was extended to the language it actually writes.

Agenten påminns när den påstår sig ha lagat något utan att ha kört det. Varje verklig utlösning av regeln granskades sedan mot de inspelade passen, och regeln skrevs om utifrån vad granskningen visade: den läser numera vad ett verkligt test av just den ändringen är, och kontrollen som kör agentens egna tester för att se dem falla först utökades till det språk den faktiskt skriver.

Existing code costs moreBefintlig kod kostar mer

The same requirements cost 3.5× more when the agent works inside code that already exists than on an empty folder, and the measured mechanism is avoidance, not editing: the work goes around the old code rather than through it. Useful when you plan what to hand it, and it is why the benchmark now includes existing-code tasks rather than green fields only.

Samma krav kostar 3,5 gånger mer när agenten arbetar i kod som redan finns än i en tom mapp, och den uppmätta mekanismen är undvikande, inte redigering: arbetet går runt den gamla koden i stället för genom den. Bra att veta när man planerar vad man lämnar över, och därför innehåller testunderlaget numera uppgifter i befintlig kod, inte bara tomma mappar.

The tooling is measured tooVerktygen mäts också

Whole recorded sessions are read back, not just their outcomes, and a surprising share of lost time turns out to be in the tooling around the model rather than in the model itself. Each case found that way becomes a fixed defect with a test that fails without the fix, so the same minute is never lost twice.

Hela inspelade arbetspass läses tillbaka, inte bara utfallen, och en förvånande del av den förlorade tiden visar sig ligga i verktygen runt modellen snarare än i modellen själv. Varje sådant fall blir ett åtgärdat fel med ett test som faller utan åtgärden, så att samma minut aldrig går förlorad två gånger.

Against a cloud subscriptionJämfört med en molnprenumeration

A typical cloud AI provider charges $200 per user per month for its top coding-assistant plan. At 9.92 SEK per USD that is 1,984 SEK per month, or 23,808 SEK per year, for each seat. The build and installation are a one-time cost and the software a fixed monthly fee; the cloud subscription grows with every seat. And the build has no usage limits: no quotas, no caps on requests and no billing per token. The hardware is yours, so it can work around the clock, every day of the year.

The cheaper $20 to $40 plans are made for suggestions and chat, with usage caps that an agent working all day through a codebase uses up quickly, and heavy daily agent work can reach the caps of the $100 plans too. Teams that build with agents every day end up on the top plans or pay per token, and that is the comparison in the table below. How many people each build servesHur många varje bygge räcker till

Two limits decide it. Memory sets how many agents can hold a conversation at once: the model takes about 29 GB, and each seat takes more the larger its context window. Speed is shared: agents working at the same moment split the card's throughput. Between tasks a person reads, reviews, approves and writes the next request, so a card serves more people than it has agents generating at any one moment.

Två gränser avgör. Minnet bestämmer hur många agenter som kan hålla en konversation samtidigt: modellen tar ungefär 29 GB, och varje plats tar mer ju större kontextfönster den har. Hastigheten delas: agenter som arbetar i samma stund delar på kortets kapacitet. Mellan uppgifterna läser, granskar och godkänner personen och skriver nästa beställning, så ett kort räcker till fler personer än det har agenter som genererar i samma ögonblick.

Stated plainlySagt rakt ut

Capability scales with the modelFörmågan skalar med modellen

Capability tracks the local model you run. On the benchmark, some categories of bug are fixed reliably and others are not, and the numbers are recorded rather than rounded up.

The agent is not tied to one model. It speaks to any local model server through a single contract, so the next step is larger models on larger hardware: a workstation card or a server GPU runs models several times the size of the tested one, and the measurement bench re-runs the same sealed studies on each so the gain is a number rather than a claim.

Förmågan följer den lokala modell ni kör. I testunderlaget lagas vissa sorters fel pålitligt och andra inte, och siffrorna redovisas i stället för att rundas uppåt.

Agenten är inte bunden till en modell. Den talar med vilken lokal modellserver som helst genom ett enda kontrakt, så nästa steg är större modeller på större hårdvara: ett arbetsstationskort eller ett server-GPU kör modeller flera gånger så stora som den testade, och mätverkstaden kör om samma låsta studier på var och en så att vinsten blir en siffra i stället för ett påstående.

Requires local hostingKräver lokal modell

It needs a model server on the machine or the network: a 16 GB GPU runs the tested configuration comfortably. There is no fallback to a hosted API, by design.

Den behöver en modellserver på maskinen eller i nätverket: ett grafikkort med 16 GB kör den testade konfigurationen med marginal. Det finns medvetet ingen reservväg till ett moln-API.

Utvecklad och uppmätt på Windows, inklusive de skalbeteenden som fäller naiva agenter där. Andra plattformar täcks för närvarande inte av testsviten.

Den är byggd för att arbeta med en människa som godkänner stegen, inte för att lämnas ensam mot produktionssystem.
